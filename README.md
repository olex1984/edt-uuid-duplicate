# Поиск дубликатов UUID для 1С:EDT

Плагин для **1С:EDT** (Eclipse RCP), который находит дубликаты UUID в файлах
метаданных проекта и показывает их в Problems view и отдельной панели
«Дубли UUID». Работает на публичных API Eclipse, без внешних зависимостей
и без `com._1c.*`.

**Версия:** 1.0.0 · **Платформа:** 1С:EDT 2025.1+ / 2026.x · **Java:** 17+

---

## Зачем это

В конфигурациях 1С UUID — идентификатор элемента метаданных. Если один UUID
случайно оказался в двух файлах (копирование обработок, слияние, шаблоны),
EDT может вести себя непредсказуемо. Плагин находит такие ситуации сразу
и показывает, **где именно** одно и то же значение встречается.

Отличие от поиска регулярным выражением: плагин разбирает XML потоково (StAX)
и учитывает **только собственный атрибут `uuid`** элемента. Атрибуты-ссылки
(`ref`, `typeId`, `valueTypeId`), текст и комментарии не дают ложных срабатываний.

## Возможности

- Сканирует `.mdo` (и `.xml` по настройке) проектов 1С:EDT.
- Находит **межфайловые** дубли (UUID в 2+ файлах) и **внутрифайловые** повторы.
- Маркеры в **Problems** с переходом к строке.
- Панель **«Дубли UUID»**: дерево «UUID → файлы и строки», фильтр, сортировка,
  «Развернуть всё», копирование UUID, переход в файл.
- **Автообновление** по сохранению файлов (debounce 750 мс) в фоне, без блокировки UI.
- Кэш индекса в workspace: повторный скан не перечитывает неизменённые файлы.
- Настройки рабочего пространства и проекта.
- **Экспорт CSV и текстового отчёта** в фиксированном формате
  (см. «Форматы экспорта» в плане).

### Как это выглядит

```
Дубли UUID
Проект          UUID                                  Файлов  Вхождений  Тип
Posthandlings   98adef27-c09b-4dd3-a7ed-72b4a2892a1d       3          3  межфайловый
  ├─ src/ExternalDataProcessors/П_.../П_....mdo:2
  ├─ src/ExternalDataProcessors/П_.../П_....mdo:2
  └─ src/ExternalDataProcessors/П_.../П_....mdo:2

Problems
⚠ Дубликат UUID 98adef27-…: тот же UUID используется в 3 файле(ах): …
```

## Установка

Соберите jar (см. раздел «Сборка») или возьмите готовый из релизов,
затем скопируйте его в `dropins` установленного EDT и перезапустите:

```bash
EDT=/opt/1C/1CE/components/1c-edt-2026.2.2+21-x86_64
sudo mkdir -p "$EDT/dropins"          # папки может не быть — создайте её
sudo cp ru.citcer.uuidcheck_1.0.0.jar "$EDT/dropins/"
```

> **Каталог `dropins` часто отсутствует** в поставке EDT — это нормально,
> он создаётся вручную. Регистрацией бандла из него занимается
> `org.eclipse.equinox.p2.reconciler.dropins`, который уже входит в EDT.

Если плагин не подхватился — один раз запустить EDT с `-clean`.
Проверка: `Справка → О системе Eclipse IDE → Installation Details → Plug-ins`
→ `ru.citcer.uuidcheck`.

> **Просто положить jar в `plugins/` — не работает.** Активный список бандлов
> задаётся файлом `configuration/org.eclipse.equinox.simpleconfigurator/bundles.info`
> (~1200 строк), и jar, которого там нет, Equinox не устанавливает: `-clean`
> этого тоже не исправляет. Проверено на EDT 2026.2.2: в `ss` 846 бандлов,
> бандла из `plugins/` среди них нет; после копирования того же jar в
> `dropins/` reconciler добавляет запись в `bundles.info` и бандл появляется.
> Если всё же нужен именно `plugins/`, в `bundles.info` придётся вручную
> добавить строку `ru.citcer.uuidcheck,1.0.0,plugins/ru.citcer.uuidcheck_1.0.0.jar,4,false`.

> `dropins` предпочтительнее, чем `plugins`: установка в `plugins` может быть
> удалена при обновлении EDT.

> Если EDT установлен системно (`/opt/...`, владелец `nobody`/`root`), то и
> `dropins`, и `bundles.info` требуют прав root — либо используйте отдельную
> копию EDT в домашнем каталоге для разработки.

## Быстрый старт

1. Откройте проект 1С:EDT в рабочем пространстве.
2. Правый клик по проекту → **«Проверить дубликаты UUID»**.
3. Откроется панель «Дубли UUID»; в Problems появятся маркеры.
4. Двойной клик по строке UUID — развернуть список файлов; по файлу — перейти
   на нужную строку.

Плагин также работает автоматически: при старте EDT и после сохранения `.mdo`.
Подробно — в [инструкции по эксплуатации](Инструкция_по_эксплуатации.md).

## Настройки

`Окно → Параметры → UUID-проверка` (рабочее пространство) и
`Свойства проекта → UUID-проверка` (проект).

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `scan.extensions` | `mdo,xml` | Расширения сканируемых файлов |
| `scan.excludeDirs` | `.git,.settings,out,build,bin,target,node_modules,.idea` | Исключаемые каталоги (по имени) |
| `scan.debounceMs` | `750` | Пауза перед автосканом |
| `severity.crossFile` | `WARNING` | Важность межфайловых дублей |
| `intraFile.mode` | `WARN` | Политика внутрифайловых повторов |
| `markers.max` | `500` | Лимит групп с маркерами |
| `export.csvBom` / `export.csvSeparator` | `false` / `;` | Параметры CSV |

Полный список — в [инструкции](Инструкция_по_эксплуатации.md#4-настройки).

## Сборка из исходников

Требуется Eclipse IDE for RCP and RAP Developers (PDE) либо JDK 17+ и
плагины целевой EDT.

```bash
export EDT_PLUGINS=/opt/1C/1CE/components/1c-edt-2026.2.2+21-x86_64/plugins
export JAVA_HOME=/opt/1C/1CE/components/axiom-jdk-full-25.0.4+5-x86_64
./build.sh      # → build/ru.citcer.uuidcheck_1.0.0.jar
./test.sh       # JUnit: парсер + экспорт
```

Для разработки в PDE: импортировать три проекта (`ru.citcer.uuidcheck`,
`ru.citcer.uuidcheck.tests`, `releng/ru.citcer.uuidcheck.target`), активировать
target `edt-2026.2.target` (или `edt-2025.1.target`) и запустить
`Run As → Eclipse Application`.

> ⚠️ **Путь к целевой платформе.** В `.target`-файлах указан абсолютный путь
> `/opt/1C/1CE/components/1c-edt-2026.2.2+21-x86_64` — он есть только на машине,
> где плагин разрабатывался. Перед импортом откройте оба файла в
> `releng/ru.citcer.uuidcheck.target/` и замените `path="..."` в элементе
> `<location>` на каталог вашей установки EDT, либо поправьте путь через
> `Preferences → Plug-in Development → Target Platform → Edit`.
> `build.sh` и `test.sh` правки не требуют: путь к плагинам EDT передаётся
> переменной `EDT_PLUGINS`, а JDK — `JAVA_HOME`.

> При запуске в чистом Eclipse RCP (не EDT) добавьте VM-аргумент
> `--add-modules=ALL-SYSTEM`, иначе `javax.xml.stream` не экспортируется.
> В 1С:EDT он уже прописан в `1cedt.ini`.

## Совместимость и ограничения

- Сканируются только проекты, открытые в рабочем пространстве.
- Поддерживаются `.mdo`/`.xml`; `.cf`, `.dt`, `.epf` — вне области (нужен
  отдельный адаптер).
- Маркеры `persistent=false`: восстанавливаются после фонового скана при старте.
- В form-редакторе `.mdo` переход по строке может открыть текстовый редактор.
- Внутрифайловый повтор по UUID, который уже является межфайловым дублем,
  отдельной группой не выводится.
