# Плагин «Поиск дубликатов UUID» для 1С:EDT — инструкция по эксплуатации

**Версия:** 1.0.0
**Платформа:** 1С:EDT 2025.1+ / 2026.x (Eclipse RCP, Java 17+)
**Документы:** [план реализации](План_реализации_плагина_UUID_EDT.md) · [архитектура](Архитектура_плагина_поиска_дублей_UUID_EDT.md) · [README](README.md)

---

## 1. Что делает плагин

Плагин ищет дубликаты UUID в файлах метаданных проекта 1С:EDT и показывает их
в привычных местах Eclipse.

- Сканирует файлы с расширениями из настройки (по умолчанию `.mdo` и `.xml`).
- Берёт **только собственный** атрибут `uuid` XML-элемента. Атрибуты-ссылки
  (`ref`, `typeId`, `valueTypeId`, `objectId`, `classId`), текст и комментарии
  не учитываются — это принципиальное отличие от поиска регулярным выражением.
- Сравнивает UUID без учёта регистра (приводит к нижнему).
- Находит два вида проблем:
  - **межфайловый дубль** — один UUID в двух и более разных файлах (основная категория);
  - **внутрифайловый повтор** — один UUID дважды в одном файле (отдельная категория).
- Показывает результат в **Problems** (маркеры на строке с `uuid`) и в виде
  **«Дубли UUID»** (дерево: группа UUID → все файлы с номерами строк).
- Умеет экспортировать CSV и текстовый отчёт в фиксированном формате (см. §5).

**Не проверяет:** `.cf`, `.dt`, `.epf`, `.erf` (это не файловая область проекта),
UUID вне workspace, файлы вне EDT-проектов.

## 2. Когда плагин срабатывает

### 2.1. Автоматически

| Событие | Что происходит |
|---|---|
| Запуск EDT | Фоновый прогрев открытых EDT-проектов (если включено «Проверять при запуске EDT»). |
| Сохранение/изменение `.mdo`/`.xml` | Через **750 мс** после последнего изменения (debounce) запускается фоновое сканирование проекта. |
| Добавление/удаление/перемещение файла | То же — пересчёт индекса и маркеров проекта. |
| Открытие проекта | Проект сканируется заново. |
| Изменение настроек проекта | Пересканирование (включение, расширения, внутрифайловые повторы). |
| Закрытие/удаление проекта | Индекс проекта и его маркеры удаляются. |

Все автоматические сканы выполняются в фоне (`WorkspaceJob`), UI не блокируется.
Повторный скан **не читает заново неизменённые файлы**: они берутся из кэша по
`modificationStamp` и размеру.

Автоматика **не срабатывает** для:

- не-EDT проектов;
- проектов, у которых выключен автоскан (общий или проектный);
- исключённых каталогов (по имени папки на любой глубине);
- файлов, помеченных как derived / team-private / linked (linked можно включить);
- файлов с расширением, которого нет в настройке.

### 2.2. Вручную

- **Правый клик по проекту → «Проверить дубликаты UUID»** — полный скан
  (кэш игнорируется) и открытие вида «Дубли UUID».
- Ручная проверка **работает даже при выключенном автоскане** проекта.
  Если проект вообще не похож на EDT-проект, плагин сообщит об этом.
- Команда **«Пересканировать все проекты»** (`ru.citcer.uuidcheck.commands.rescanAll`)
  существует, но пункта меню по умолчанию не имеет. При необходимости назначьте
  ей клавишу: `Параметры → Общие → Клавиши`.

## 3. Где смотреть результат

### 3.1. Problems view

На каждое вхождение дубля создаётся маркер:

> Дубликат UUID 7c9e4a1b-…: тот же UUID используется в 3 файле(ах):
> src/Catalogs/A.mdo:5, src/Catalogs/B.mdo:7

- Важность межфайловых дублей — **WARNING** по умолчанию (можно переключить на ERROR
  в параметрах).
- Клик по маркеру открывает файл на нужной строке.
- Маркеры **не сохраняются между сессиями** (`persistent=false`): после рестарта
  они появятся снова после фонового скана.
- Действует лимит: если групп больше `markers.max` (по умолчанию 500), маркеры
  создаются для первых 500 групп, а на проекте появляется сводный маркер.
  В виде при этом видны **все** группы.
- Если включена настройка «Помечать маркером неразобранные файлы», на файлах
  с ошибкой XML/доступа появится WARNING «Файл не разобран: …».

### 3.2. Вид «Дубли UUID»

Открыть: `Окно → Показать вид → Другое… → 1С:EDT → Дубли UUID`
(или командой «Проверить дубликаты UUID»).

Колонки: **Проект · UUID · Файлов · Вхождений · Тип · Файлы и строки**.

- **Сортировка** — клик по заголовку колонки (повторный клик меняет направление).
- **Фильтр** — поле сверху ищет по UUID, имени проекта и по путям файлов.
- **Дерево**: двойной клик по строке UUID **разворачивает полный список файлов**
  с номерами строк; двойной клик по файлу открывает его на нужной строке.
- Кнопки на панели вида: **«Развернуть всё»**, **«Свернуть всё»**, экспорт.
- Контекстное меню: открыть, копировать UUID, развернуть/свернуть, экспорт.
- В строке состояния — количество групп, просканированных файлов и файлов с ошибками.
- Вид показывает **все проиндексированные проекты**; раскладка запоминается.

## 4. Настройки

### 4.1. Общие: `Окно → Параметры → UUID-проверка`

| Настройка | По умолчанию | Назначение |
|---|---|---|
| Автоматически проверять проекты | включено | Глобальный выключатель автоскана. |
| Расширения файлов | `mdo,xml` | Через запятую, без точек. `.xml` нужен для работы с XML-дампами метаданных. |
| Исключаемые каталоги | `.git,.settings,out,build,bin,target,node_modules,.idea` | Сравнивается **имя папки** на любой глубине. |
| Сканировать linked-ресурсы | выключено | Сканировать ли папки/файлы, подключённые ссылкой. |
| Задержка объединения событий, мс | `750` | Пауза после серии изменений перед сканом. |
| Проверять при запуске EDT | включено | Фоновый прогрев при старте. |
| Порог «широкой» дельты, файлов | `200` | Если изменено больше файлов, маркеры проекта пересоздаются целиком (на сам скан не влияет). |
| Важность межфайловых дублей | `WARNING` | Или `ERROR` — тогда маркер будет ошибкой. |
| Максимум групп с маркерами | `500` | Лимит маркеров в Problems; остальное — в виде и сводном маркере. |
| Внутрифайловые повторы | `WARN` | `IGNORE` — не искать, `WARN`/`ERROR` — важность. |
| Добавлять BOM в CSV (для Excel) | выключено | UTF-8 BOM в начале CSV. |
| Разделитель CSV | `;` | Разделитель полей в CSV-экспорте. |
| Писать пустой отчёт при отсутствии дублей | выключено | Для CI: создать пустой `uuid_report.txt`, даже если дублей нет. |
| Показывать диалог о новых дублях | выключено | Всплывающее уведомление, когда после скана появились новые межфайловые дубли (при первом скане не показывается). |
| Помечать маркером неразобранные файлы | выключено | WARNING на файлах, которые не удалось разобрать. |

### 4.2. Уровень проекта: `Правый клик по проекту → Свойства → UUID-проверка`

Можно переопределить только:

- **Проверять этот проект** — выключить шумный/сгенерированный проект;
- **Расширения файлов** — свой набор для проекта;
- **Внутрифайловые повторы** — своя политика для проекта.

Сохранение настроек проекта запускает пересканирование. Выключение автоскана
**не мешает** ручной команде «Проверить дубликаты UUID».

## 5. Экспорт

Доступен из вида «Дубли UUID»: кнопки на панели или контекстное меню.

- **CSV** — `uuid_duplicates_posthandlings.csv` по умолчанию.
  Формат: UTF-8, разделитель `;`, заголовок `UUID;Файл`, перевод строки `\r\n`,
  одна строка на пару (UUID, файл), сортировка по UUID и пути. Только межфайловые
  дубли.
- **Текстовый отчёт** — `uuid_report.txt` по умолчанию. Эмодзи-заголовки,
  статистика (всего файлов, XML, MDO, уникальных UUID, дублирующихся) и список
  дублей с относительными путями. Если дублей нет, файл не создаётся (кроме
  случая, когда включена опция «писать пустой отчёт»).
- Пути в экспорте — **относительно корня проекта** с разделителем `/`.
- Экспорт сохраняется туда, куда укажете в диалоге, и **не меняет** индекс.

## 6. Кэш и производительность

- Индекс хранится в кэше workspace:
  `<workspace>/.metadata/.plugins/ru.citcer.uuidcheck/uuid-index-v1.json`.
- При старте кэш читается, затем файлы проверяются по `modificationStamp` и
  размеру: изменившиеся пересканируются, остальные берутся из кэша.
- Кэш пишется после сканов (не чаще раза в 5 секунд) и при выходе из EDT.
- Кэш можно **безопасно удалить** (при закрытом EDT) — следующий запуск выполнит
  полный скан.
- Скан 5 000 `.mdo` рассчитан на единицы секунд; UI не блокируется, прогресс и
  отмена — в стандартном индикаторе Eclipse.

## 7. Ограничения и особенности

1. Сканируются только проекты, открытые в workspace EDT.
2. Маркеры не сохраняются между сессиями — восстанавливаются после фонового скана.
3. В form-редакторе `.mdo` навигация по строке может открыть текстовый редактор —
   это ожидаемо (см. риск R6 плана).
4. Если UUID является межфайловым дублем, внутрифайловый повтор по нему отдельной
   группой не выводится (межфайловый важнее).
5. `.xml` в настройках по умолчанию включён для работы с XML-дампами; в чистом
   EDT-проекте таких файлов почти нет, но в дампах возможен шум.
6. Исключения каталогов задаются **именами**, а не путями.
7. При выключении автоскана уже созданные маркеры остаются до следующего
   пересчёта (закрытие проекта, ручная проверка или изменение файлов).
8. Диалог о новых дублях срабатывает только начиная со второго скана проекта.

## 8. Диагностика

**Понять, что плагин установлен и активен:**
`Справка → О системе Eclipse IDE → Installation Details → Plug-ins` →
`ru.citcer.uuidcheck` (вендор `Oleg Zitzer`, версия 1.0.0).

**Где лог:** `<workspace>/.metadata/.log`. Записи плагина помечены
`!ENTRY ru.citcer.uuidcheck`.

**Вид пуст, хотя дубли есть:**
- проверьте строку состояния вида (сколько файлов просканировано и с ошибками);
- проверьте, что проект — EDT (`DT-INF/PROJECT.PMF`, `src/Configuration/Configuration.mdo`
  или хотя бы один `.mdo` в `src`);
- проверьте расширения и исключённые каталоги;
- проект не выключен в его свойствах (ручная проверка работает и при выключенном
  автоскане, но проект всё равно должен быть EDT).

**Маркеры есть, а вида нет:** откройте `Окно → Показать вид → Другое… → 1С:EDT → Дубли UUID`.

**Сбросить кэш:** закрыть EDT, удалить папку
`<workspace>/.metadata/.plugins/ru.citcer.uuidcheck/`, запустить EDT.

## 9. Типовые сценарии

**Быстрая проверка после правки.** Ничего делать не нужно: сохраните файл,
через ~1 секунду маркеры и вид обновятся сами.

**Полная проверка перед коммитом.** Правый клик по проекту →
«Проверить дубликаты UUID». Кэш игнорируется, сканируются все файлы.

**Разобрать конкретный дубль.** В виде разверните строку UUID (двойной клик) —
увидите все файлы и строки; двойной клик по файлу откроет его на нужном месте.

**Поделиться результатом.** Экспортируйте CSV или отчёт из вида и передайте файл.

**Отключить шумный проект.** Свойства проекта → UUID-проверка → снять
«Проверять этот проект». Автоскан перестанет его трогать.
