# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются для актуальной ветки `main`.

| Версия | Поддержка |
|---|---|
| 1.0.x | ✅ да |
| более ранние | ❌ нет |

## Как сообщить об уязвимости

**Не создавайте публичную задачу.** Публичное обсуждение до выхода
исправления раскрывает проблему тем, кто ещё не обновился.

Приватный канал: **oleg.zitzer@gmail.com**

Тема письма: `[SECURITY] edt-uuid-duplicate: <краткое описание>`.

В письме желательно указать:

- версию плагина (`Справка → О системе Eclipse IDE → Installation Details → Plug-ins`);
- версию 1С:EDT и ОС;
- шаги воспроизведения или минимальный пример;
- оценку влияния: что может сделать атакующий;
- по желанию — предлагаемое исправление.

Если предпочитаете зашифрованную переписку, напишите на тот же адрес —
пришлю открытый ключ.

## Модель угроз

Чтобы отчёт был по адресу, полезно знать, как устроен плагин.

**Плагин работает полностью локально:**

- не открывает сетевых соединений, не отправляет телеметрию и статистику;
- не загружает и не исполняет удалённый код;
- читает файлы проектов, открытых в рабочем пространстве EDT;
- пишет только кэш индекса в state location рабочего пространства
  (`.metadata/.plugins/ru.citcer.uuidcheck/uuid-index-v1.json`);
- пишет файлы экспорта только туда, куда явно указал пользователь.

**Работа с недоверенным XML.** Сканируемые `.mdo`/`.xml` — это входные данные,
которые могут прийти из чужого репозитория. Парсер `UuidXmlParser` собирает
`XMLInputFactory` с отключёнными DTD и внешними сущностями
(`SUPPORT_DTD=false`, `isSupportingExternalEntities=false`,
`IS_REPLACING_ENTITY_REFERENCES=false`), поэтому классические XXE и
billion-laughs через DTD не проходят. Если найдёте обход — это интересно.

**Экспорт CSV.** Значения экранируются по RFC 4180 (кавычки удваиваются,
поля с разделителем, кавычкой или переводом строки берутся в кавычки).
Сами UUID проходят строгую проверку по регулярному выражению, поэтому
подстановка формул в таблицы через UUID невозможна.

**Чего плагин не делает:** не проверяет подписи, не является песочницей для
проекта и не защищает от вредоносного кода в самом проекте 1С — он лишь
читает XML-файлы метаданных.

## Что не считается уязвимостью

- Плагин показывает «дубли UUID», которых, по мнению пользователя, быть не
  должно, или не показывает ожидаемых. Это вопрос корректности, а не
  безопасности — создавайте обычную задачу.
- Отсутствие цифровой подписи jar. Распространение идёт через GitHub Releases
  и GitVerse; проверяйте контрольную сумму из описания релиза.
- Медленная работа или повышенный расход памяти на очень больших проектах.
  Это ограничение производительности; сообщайте как обычную задачу
  с указанием размеров проекта.
- Предупреждения системы о неподписанном или «недоверенном» бандле при
  установке из `dropins/` — ожидаемое поведение EDT.
- Уязвимости в самой 1С:EDT, JDK или Eclipse. Сообщайте о них
  соответствующим вендорам; если проблема проявляется из-за кода плагина —
  напишите нам.
